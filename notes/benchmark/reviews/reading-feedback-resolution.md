# Benchmark 独立反馈处理与 paper-reading 候选评估

输入为用户与 ChatGPT 对照原始 PDF 的逐篇评价，原文保存在[反馈记录](../../../evolution/feedback/benchmark-paper-reading-2026-11-26.md)。分数用于描述当时的阅读体验。修订据各版本的论文正文、附录及已有源码完成，六篇是候选设计依据和回归材料。

## Skill 缺口与执行归因

| 类型 | 此次证据 | 处理方式 |
| --- | --- | --- |
| Skill 未充分覆盖 | 正式版列出必须关注的内容，但缺少如何按关键贡献分配篇幅和读到多深的判断依据。原候选规定至少一个案例、公式和结果，容易在讲完一个例子后停止追查。 | 用贡献与证据组织精读，按结论重要性追读附录、反例和适用边界。 |
| 已有要求执行不到位 | 正式版已要求关键数字有定位、关注实验和附录、区分作者结果与解释，仍出现 NIKA 图表引用错误和 AgenticOpsEval 赛事总数误归。 | 起草时建立按贡献的小型证据索引。写入单篇时按实际版本复核定位，并核对范围、分母和对照条件。 |
| 论文类型需求 | Benchmark 的纳入门禁、真值粒度、难度、评分对象与激励对理解主张至关重要。已有 AIOps Skill 可提供领域细节。 | 候选只给不同论文类型的阅读重点，复用既有领域 Skill。 |
| 来源与版本 | RCABench 正式版改图号并扩充难度讨论；AgenticOpsEval scorer 不可核验，CTBench 专家筛选工时未披露。 | 绑定版本，对缺失证据保留未决。 |
| 科研学习偏好 | 用户希望解释机制如何运行、为何有此设计、实际案例如何支撑结论。篇幅和统一结构无法衡量这些目标。 | 用原图、实验对照和失败例讲清重要机制，按贡献灵活分配深度。 |

两条经验分别保留「用贡献覆盖替代篇幅代理」和「按版本与分母核对评分和标签」；见 Experience Memory 的 `exp-77ed5c77884f`、`exp-8da9d9cb732b`。

## 候选与评价

新版 `skill-paper-reading-20261126t093120z-7ac57a` 基于当前正式 Skill，延续[上一待审候选](../../../evolution/skill-proposals/skill-paper-reading-20261126t063945z-d438db/changes.diff)区分初步阅读与全文精读的用意，用贡献导向替代固定案例/公式数量。新版保留笔记、证据、知识整合和 Git 工作流，按论文类型选择阅读重点，允许对核心引用限量补读。查看[新版 diff](../../../evolution/skill-proposals/skill-paper-reading-20261126t093120z-7ac57a/changes.diff)与[工具评估](../../../evolution/skill-proposals/skill-paper-reading-20261126t093120z-7ac57a/evaluation.md)。

工具结果是 **Inconclusive**，静态检查无报错。评估报告标出的原条目文本变更来自全文阅读段的改写，方法、实验、附录与局限性要求仍由新段落覆盖。对已知样本的检查见下表。现实中的论文修订同时受详细人工反馈影响，无法将变化归因于候选。建议进入人工审阅，暂缓应用，等用户结合新版笔记和另一种论文类型判断其可迁移性。
