# AIOps Benchmark 研究缺口

下列问题来自六篇论文的交叉比较以及对本地知识库证据边界的检查。按“领域缺口”和“本地待补证据”区分；不把待核验风险当作已证实问题。

## 领域缺口

1. **Ground Truth 的因果有效性和不确定性**：注入点、最早影响点、传播节点、故障结束和恢复可能并不重合。不同论文使用注入规范、工程记录、专家标签或参考路径，跨基准尚无统一的可追溯不确定标签。
2. **故障传播的可比表示**：层级根因标签、因果链、专家诊断路径和遥测关联分别覆盖传播的不同部分；如何区分根因、症状、影响范围及多根因仍需统一任务定义。
3. **Shortcut / 泄漏审计**：复杂度提升和多模态本身不保证无泄漏。注入模板、节点角色、故障时间、候选集、重复事件和命令响应都可能暴露答案。需要按事件/故障族/拓扑的切分和可复现负对照。
4. **Agent 过程质量的构念效度**：最终正确、读取过证据、覆盖专家路线、形成因果判断是不同指标。单一路径覆盖可能惩罚等价调查；证据覆盖也可能“引用而未使用”。
5. **资源与安全评价**：论文的 reasoning length、token、工具调用、诊断期间网络影响各自不同；安全建议、沙箱验证和真实执行影响尚未统一评估。
6. **跨域外部效度**：受控测试床、真实历史遥测、仿真网络、脱敏维护单和比赛数据的代表性不同，模型在不同设置下结果不可直接外推。
7. **数据演进与版本管理**：公开论文、数据集当前版本、项目主分支和评估器可能不同步；需锁定版本、变更记录和可复现基准协议。

## 本地知识库待补证据

- 尚无挑战赛数据的本地样本、字段字典、拓扑/节点角色、采样率、数据时间跨度、许可和版本清单，因此无法与六篇基准作定量差异比较。
- 用户提出的 inode、process count、fd 等候选特征及故障时间边界、角色绑定、长尾类别、传播范围均需通过数据生成机制、统计和因果对照核验。
- 尚未整理挑战赛现有 AD/RCA 基线、切分规则、指标实现、源代码版本和公开复现入口。
- 尚未确认 Agent 能读取的工具、上下文和数据范围，也没有同一基准下对传统算法、LLM 与 Agent 的成本/安全对照。

## 可检验问题

1. 在按故障族、节点、时间和拓扑分组的 holdout 下，性能是否显著低于随机切分？哪些简单规则能复现模型成绩？
2. 去除/置换 inode、process count、fd、时间戳和角色字段时，诊断效果如何变化？这些字段在正常对照中是否也能识别节点或注入模板？
3. 根因时间、首个异常时间、告警时间、影响开始与恢复边界是否分别可定位？标签分歧如何表示？
4. 多模态证据和拓扑边是否确实提升跨节点/跨故障泛化，而非依赖 entity ID？
5. Agent 的正确答案能否引用并验证必要证据？同一结论是否存在多条等价调查路线？如何同时报告路线、证据、Token、时间、调用和安全影响？
6. 哪些数据字段、事件片段、代码和 evaluator 可以在许可范围内公开，使第三方复现？
