# 论文科研知识提取

## 目的与边界

把已经完成的论文精读成果整理成技术细节充分、可追溯的知识档案，并按需要导出跨论文资料。

~~~text
完整论文精读笔记 + 重点事实回查原文
→ 结构化知识档案
→ 按请求开展跨论文 / 研究问题综合
→ 校验并导出 Markdown、JSONL 和可选压缩包
~~~

本 Skill 是精读完成后的知识提取层，不重新实现 `paper-reading`、`knowledge-review` 或 `knowledge-query`：

- [paper-reading](../paper-reading/SKILL.md)：完整阅读尚未精读的论文。
- [knowledge-review](../knowledge-review/SKILL.md)：在笔记或档案基础上开展有依据的跨论文比较。
- [knowledge-query](../knowledge-query/SKILL.md)：对已积累的知识做只读检索、比较与解释。
- [learning-batch](../learning-batch/SKILL.md)：编排新的通用论文批次。
- [aiops-learning-batch](../aiops-learning-batch/SKILL.md)：仅在任务属于研究问题驱动的 AIOps 批次时使用。

需要时调用这些既有 Skill，不修改它们的行为。本 Skill 负责建立档案和导出结构化成果，并将入口加入现有索引。

## 输入与证据顺序

接受一篇已精读论文、一组稳定论文 ID，或一个明确的专题目录。从知识库根目录检查 `INDEX.md`、对应的 `papers/<paper-id>/notes.md`、`knowledge-card.md`、已有知识档案以及 `sources/papers/` 下的 PDF。

使用证据的优先顺序：

1. 原始 PDF：重点核验方法机制、公式、新颖性边界、实验数值、消融和相互冲突的说法。
2. 有原文依据的完整精读笔记。
3. 知识卡片。
4. 批次 Review 或综合报告。

知识卡片和 Review 用于导航与比较，不得作为论文方法的唯一来源。不得从标题或摘要推断完整方法。如果完整精读笔记缺失或不充分，先遵循 `paper-reading` 完成精读；精读完成前将提取状态记为未完成。如果关键主张既无法从 PDF 核验，笔记也没有提供依据，则写“待确认”，保留证据边界，不靠记忆补写。

始终区分以下证据类别：

- **作者主张**：研究动机、声称的贡献或作者解释。
- **实验支持**：报告的实验实际测量和支持的内容，以及其范围。
- **本知识库分析**：方法迁移推断、潜在局限或研究假设。

重要主张旁应标注来源定位：PDF 文件名、章节、印刷页码或 PDF 页码，以及表、图、公式或附录编号（可获得时）。不得编造页码；无法核验时标为“待确认”。

## 工作模式

### 单篇提取

1. 确认论文具有完整 `notes.md`，确定稳定 `paper-id`、知识卡片和原始资料路径。
2. 检查已有 `knowledge-dossier.md`。若档案记录的精读笔记、知识卡片和 PDF 哈希均与当前文件一致，则报告未变化并跳过重写，除非用户要求刷新。否则只更新该论文档案和相关索引入口。
3. 回查 PDF 中影响结论的事实：核心公式 / 目标、数据与任务粒度、关键结果及消融、新颖性边界、作者明确的局限，以及笔记中的冲突。
4. 使用[知识档案模板](templates/knowledge-dossier.md)编写 `papers/<paper-id>/knowledge-dossier.md`。依论文复杂度调整细节，不为凑字数扩写或重复。
5. 在档案末尾保留边界明确的机器可读 JSON 记录，以便批量 JSONL 和总览导出。
6. 在 `INDEX.md` 的合适位置增加简洁链接。除非用户明确要求，不改写既有论文笔记、知识卡片、Questions 或 Skill。

### 批量提取

1. 按用户明确指定的论文 ID 或目录发现论文。针对目录，使用稳定论文 ID 核对 PDF、完整笔记、知识卡片和 `INDEX.md`；不得暗中扩大集合。
2. 在指定导出目录或专题进度文件中维护进度清单，状态使用 `pending`、`complete`、`needs-review`，记录精读笔记、知识卡片和 PDF 的 SHA-256。通常每完成 2–5 篇就保存档案和进度，方便中断后继续。
3. 复用来源未变化且校验通过的档案。仅当 PDF、精读笔记、知识卡片、档案 schema 或用户要求变化时重新提取。
4. 逐篇生成统一档案；领域相关的研究问题通过专题配置或独立问题地图提供，不写死在通用 Skill 中。
5. 全集完成后运行 `scripts/export_knowledge.py` 校验并生成完整 Markdown、总览、JSONL 和可选 ZIP。问题地图由研究者依据证据撰写，导出脚本不生成研究空白。
6. 使用 `knowledge-review` 做有实质内容的跨论文评审；不要在导出脚本里重复实现评审。
7. 更新 `INDEX.md`，链接档案集合、完整导出、问题地图和本 Skill。

## 档案内容标准

每份档案遵循模板的 13 个部分：

1. **基本信息**：英文标题、中文译名、作者、会议 / 年份 / CCF 等级及来源、PDF 与精读笔记路径、知识卡片、核实过的代码地址、领域和方法标签。
2. **研究场景**：真实或基准场景、数据模态和维度、输入 / 输出、异常粒度、运维需求。
3. **研究问题**：描述任务条件、现有实践的失败情形和未完成目标；不要把模块名称当作研究问题。
4. **核心挑战**：说明具体现象、成因、对检测的影响，以及传统方法难以处理的原因，并标注 PDF 定位。
5. **已有方法不足**：比较方法类型、基本假设、在目标场景下的失败方式和论文所针对的差距；区分作者主张与直接实验事实。
6. **核心思想**：用通俗而准确的语言解释整套设计的必要性，使读者形成忠实的端到端理解。
7. **技术创新**：逐项说明名称、对应挑战、机制、新颖性边界、实验支持、适用条件和限制。不得把常见 Transformer、GNN、TCN 或对比目标本身当成创新。
8. **方法详解**：说明总体架构、预处理、各模块的输入 / 操作 / 输出 / 作用、核心公式和损失、训练、推理及端到端流程。原文没有说明的部分标为“原文未明确说明”。
9. **实验依据**：整理数据集、Baseline、指标、关键数值、消融、鲁棒性 / 泛化及真实工业验证；注明每项实验能支持什么、不能证明什么。
10. **局限性**：分开列出作者明确承认的局限、基于方法 / 实验的分析推断、仍缺少的证据。未做实验只是证据边界，不代表方法必然不具备某种能力。
11. **研究启示**：可复用设计、AIOps 或其他领域迁移、Baseline 价值和待验证假设均标为“本知识库分析”，除非作者原文明确提出。
12. **相关论文**：链接稳定论文 ID，说明同题、机制相似、互补或后续关系。
13. **证据来源**：汇总关键主张的 PDF 文件名、章节 / 页码、表图公式定位；正文关键事实旁也应保留定位。

档案使用中文，保留必要英文术语。一般以约 2,000–4,000 个中文字符为参考；复杂方法可更长，只有原文材料确实有限时才更短。档案必须可独立阅读，内部路径只作追溯，不能替代技术解释。

## 结构化记录与导出

在每篇档案末尾添加模板指定的 JSON 代码块，并用模板中的精确注释包围。JSON 必须有效、UTF-8、无尾逗号，`paper_id` 与目录稳定 ID 一致。未知值使用 `null` 或明确的“待确认”，不得猜测。

从仓库根目录调用导出脚本：

~~~bash
python3 skills/paper-knowledge-extraction/scripts/export_knowledge.py \
  --paper-ids paper-a paper-b --expected-count 2 \
  --prefix paper-knowledge --jsonl-name paper-knowledge.jsonl \
  --output-dir /tmp/paper-knowledge-pilot --zip
~~~

处理 TSAD 全集时使用 `tsad-33-paper-knowledge-full`、`tsad-33-paper-knowledge-overview` 和 `tsad-paper-knowledge.jsonl` 等既定名称；其他主题选择领域无关的文件前缀。脚本校验档案章节、JSON 字段、唯一 ID、PDF / 精读笔记 / 知识卡片来源路径与哈希、记录数量，并生成合并 Markdown、总览、JSONL、独立档案副本和可选 ZIP。ZIP 不得包含 PDF。

跨论文关系章节可由研究者撰写后通过 `--overview-addendum FILE` 追加到总览。领域专属问题地图必须有证据依据，不能由关键词或导出脚本猜测。

## 验证记录

此工作流先在机制差异明显的 FlowFuse（多视角分数与 coupling-flow 融合）和 Conditional Normalizing Flows（条件生成、潜动态与 goodness-of-fit 检验）上试运行。两份档案通过章节、JSON、PDF / 精读笔记 / 知识卡片来源哈希和无 PDF ZIP 检查；同一导出器随后通过 33 篇 TSAD 档案校验。

## 质量与 Git

宣布完成前必须：

- 确认每篇目标论文有一份完整档案和一条 JSON 记录，没有重复或遗漏 ID。
- 对照 PDF 检查重要公式、新颖性边界、定量结果、消融和作者局限。
- 核对标题 / 作者 / 会议元数据、代码地址、PDF / 笔记 / 卡片路径与来源哈希。
- 检查是否区分作者陈述、实验结果和分析推断。
- 运行导出器并查看合并 Markdown、总览、JSONL、问题地图和 ZIP 内容 / 数量。
- 核对 UTF-8、无模板占位符、知识库相对链接可用；执行 `git diff --check`。
- 确认 Git staging 中不含 PDF 或无关文件。按仓库既有 `main` / `origin` 提交与推送约定执行；本地上传包可按 `.gitignore` 保留。

无法根据现有资料可靠建立结论时，将该论文状态标为 `needs-review`，写明具体证据缺口并继续其他论文。不得把未完成精读的论文标成完成，也不得编造研究空白。
