# Repository Defaults

- Follow the user's current task first; these defaults do not override an explicit request.
- For ordinary research, use the current Codex main session. Read and reuse the relevant existing `skills/*/SKILL.md`; start the full Evolution Engine only when the user explicitly requests it.
- When useful, retrieve at most five relevant Experience Memory records and reuse existing notes, PDFs, source text, and code before searching or rereading.
- Treat Experience Memory as process guidance, not evidence for current research claims. At task end, record only durable feedback or reusable lessons.
- Use an independent read-only Judge only when the stakes or evidence uncertainty warrant it. Use Skill Evolution for evidenced reusable Skill defects; do not directly rewrite Skills.
- A new paper/code note is a normal task artifact. Changes to durable cross-paper Concepts, Claims, Lessons, or Skills require a reviewable Proposal and explicit user approval; committing a note does not approve those changes.
- Before committing, stage only exact paths changed by the current task with `git add -- <paths>`. Never stage unrelated pre-existing work. Preserve existing Skill-specific commit/push behavior unless the user says otherwise.
- Keep verification proportional to task risk and value; avoid repeated checks that cannot change the decision. See [the lightweight research workflow](notes/guides/lightweight-research-workflow.md).
